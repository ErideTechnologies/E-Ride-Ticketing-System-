Goal:
Add Linear API integration so support/admin can create a Linear engineering issue directly from a support ticket.

Important:
- Do not automatically create Linear issues for every ticket.
- Only create a Linear issue when an admin/support user clicks “Create Linear Issue”.
- Keep the existing manual Linear link flow.
- If Linear API is not configured, the UI must gracefully fall back to manual copy/paste.
- Do not expose Linear details to public users.
- Do not send sensitive user information unnecessarily to Linear.
- Do not include raw Sentry stack traces in Linear.
- Do not create GitHub integration yet.
- Do not add Sentry-to-Linear automation yet.

Environment variables:
- LINEAR_API_KEY
- LINEAR_TEAM_ID_EMA optional
- LINEAR_TEAM_ID_8BT optional
- LINEAR_TEAM_ID_ERD optional
- LINEAR_DEFAULT_TEAM_ID optional

Backend:

1. Create Linear helper module.

Suggested file:
artifacts/api-server/src/lib/linearClient.ts

It must:
- initialise only if LINEAR_API_KEY exists
- expose createLinearIssue(params)
- gracefully return disabled result if LINEAR_API_KEY is missing
- never crash app if Linear is not configured

createLinearIssue params:
- teamId
- title
- description
- priority optional
- labels optional

Return:
- success boolean
- disabled boolean
- linearIssueId optional
- linearIssueKey optional
- linearIssueUrl optional
- errorMessage optional

2. Product-to-Linear team mapping.

Resolve Linear team ID using:
- productCode EMA → LINEAR_TEAM_ID_EMA
- productCode 8BT → LINEAR_TEAM_ID_8BT
- productCode ERD → LINEAR_TEAM_ID_ERD
- fallback → LINEAR_DEFAULT_TEAM_ID

If no team ID exists:
- return disabled/configuration error
- do not crash
- tell UI manual copy/paste is required

3. Create endpoint:
POST /api/support/tickets/:id/create-linear-issue

Input:
- createdByName optional
- linearTeamId optional override
- title optional
- description optional

Behavior:
- verify ticket belongs to active Eride Technologies organisation
- verify ticket does not already have a support_ticket_linear_links record with linearIssueKey
- generate Linear title/body using the same Engineering Escalation template from Step 9 if title/description not provided
- determine Linear team ID
- call Linear API
- if successful:
  - upsert support_ticket_linear_links with:
    linearIssueId
    linearIssueKey
    linearIssueUrl
    linearTeamKey or team ID
    linearStatus = created
    createdByName
    lastSyncedAt = now
  - optionally add support_ticket_status_history row if internalStatus changes
  - update ticket internalStatus to linear_created if current status is engineering_escalation_required or support_review
  - publicStatus should remain being_fixed if already being_fixed, otherwise do not force publicStatus unless necessary
- if disabled or failed:
  - do not create link
  - return clear error/disabled response

Response:
- success
- disabled
- errorMessage
- linearLink if created
- generatedTitle
- generatedDescription

4. Logging:
When Linear issue is created successfully, create an internal message or note:
- direction = internal
- channel = internal_note
- messageType = internal_update
- messageBody = “Linear issue {{linearIssueKey}} created for this support ticket.”
- deliveryStatus = not_applicable
