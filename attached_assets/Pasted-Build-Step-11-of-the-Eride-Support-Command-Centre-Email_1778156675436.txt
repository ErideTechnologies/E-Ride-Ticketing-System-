Backend requirements:

- subject

Template rules:

- Include ticketReference.
- Include productName.
- Include publicStatus.
- Do not include internal status.
- Do not include internal notes.
- Do not include Linear/Sentry/GitHub/Replit details.

3. Create endpoint:
POST /api/support/tickets/:id/send-email

Purpose:
Send a support email for a ticket and log it in support_ticket_messages.

Input:
- messageType required
- to optional
- subject optional
- bodyText optional
- bodyHtml optional
- senderName optional
- sendMode optional: "template" or "custom"

Allowed messageType:
- ticket_received
- under_review
- more_info_needed
- escalated_to_engineering
- fixed
- resolved
- closed
- reopened
- custom

Behavior:
- verify ticket belongs to active Eride Technologies organisation
- determine recipient:
  - use input.to if provided
  - otherwise use ticket.reporterEmail
- reject with 400 if no recipient email exists
- if sendMode = template:
  - generate subject/text/html from template and ticket
- if sendMode = custom:
  - require subject and bodyText
  - generate basic HTML from bodyText
- send email through support email helper
- create support_ticket_messages row:
  direction = outbound
  channel = email
  messageType = input.messageType
  senderName = input.senderName or "Eride Support"
  senderRole = "support"
  recipientName = ticket.reporterName
  recipientEmail = recipient
  recipientWhatsapp = ticket.reporterWhatsapp
  messageBody = text body sent
  deliveryStatus:
    - sent_manual if successfully sent
    - failed if provider failed
    - drafted if email disabled due to missing RESEND_API_KEY
  relatedPublicStatus = ticket.publicStatus
  relatedInternalStatus = ticket.internalStatus
- return:
  - success
  - disabled
  - deliveryStatus
  - providerMessageId if available
  - message record
