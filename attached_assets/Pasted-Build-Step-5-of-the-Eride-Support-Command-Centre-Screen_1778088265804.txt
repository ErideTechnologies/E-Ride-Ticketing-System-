Step 1 foundation is complete:

- support_products

Step 2 is complete:
- /help/report-problem
- POST /api/support/tickets
- public ticket creation works

Step 3 is complete:

- ticket dashboard works

Step 4 is complete:
- /admin/support/tickets/:id
- ticket detail page works
- status updates work
- internal notes work
- status history works
- communication copy templates work
- developer handoff generator works

Goal:
Add screenshot and attachment support to support tickets.

Important:
Do not add Linear integration yet.
Do not add Sentry integration yet.
Do not add WhatsApp/email sending yet.
Do not build full wallboard yet.
Do not build external object storage yet unless the project already has an upload/storage pattern.
Use the safest existing storage pattern in the app. If no existing storage exists, implement local/server-side upload storage suitable for development and clearly isolate it so it can later be replaced by S3/R2.

Database:

Create support_ticket_attachments table:
- id
- supportTicketId
- fileName
- originalFileName
- fileType
- mimeType
- fileSize
- storagePath
- uploadedByName nullable
- uploadedByEmail nullable
- uploadedByRole nullable
- createdAt

Relationship:
- attachment belongs to support ticket
- cascade delete if support ticket is deleted

File rules:
Allowed file types:
- image/png
- image/jpeg
- image/jpg
- image/webp
- application/pdf
- video/mp4
- video/quicktime

Allowed extensions:
- .png
- .jpg
- .jpeg
- .webp
- .pdf
- .mp4
- .mov

Maximum file sizes:
- images: 10MB
- PDFs: 15MB
- videos: 50MB

Security:
- Validate MIME type and extension.
- Do not allow executable files.
- Do not expose raw server file paths publicly.
- Store files using generated safe filenames, not original filenames.
- Preserve originalFileName separately for display.
- Attachment download/view endpoints must check that the ticket belongs to Eride Technologies organisation.
- If possible, serve attachments through an API route instead of direct public folder exposure.

Backend endpoints:

1. POST /api/support/tickets/:id/attachments

Purpose:
Upload one attachment to a ticket.

Input:
- multipart/form-data
- file required
- uploadedByName optional
- uploadedByEmail optional
- uploadedByRole optional

Behavior:
- validate ticket exists and belongs to Eride Technologies organisation
- validate file type and size
- save file
- create support_ticket_attachments row
- return attachment metadata

2. GET /api/support/tickets/:id/attachments

Purpose:
List attachments for a ticket.

Return newest first:
- id
- fileName
- originalFileName
- fileType
- mimeType
- fileSize
- createdAt
- uploadedByName
- uploadedByRole
- viewUrl/downloadUrl

3. GET /api/support/tickets/:id/attachments/:attachmentId

Purpose:
Securely view/download attachment.

Behavior:
- verify ticket belongs to Eride Technologies organisation
- verify attachment belongs to ticket
- stream or return the file
- set appropriate content type

Optional:
4. DELETE /api/support/tickets/:id/attachments/:attachmentId

Purpose:
Allow admin to delete an attachment if uploaded by mistake.

If implemented:
- delete file from storage
- delete DB row

Frontend changes:

A. Public Report Problem page:

Add optional attachment upload field:
Label:

Helper text:
