Build Step 4 of the Eride Support Command Centre: the Internal Ticket Detail Page.

Context:
Step 1 foundation is complete:
- support_organisations
- support_products
- support_tickets
- support_ticket_sequences
- generateSupportTicketReference(organisationId, productId)

Step 2 is complete:
- /help/report-problem
- GET /api/support/products
- POST /api/support/tickets
- public ticket submission works

Step 3 is complete:
- /admin/support/tickets
- GET /api/support/tickets
- dashboard summary cards
- filters
- ticket list/table
- mobile stacked cards
- row click currently shows Step 4 placeholder alert

Goal:
Create the internal ticket detail page so support/admin staff can open and manage a specific ticket.

Route:
- /admin/support/tickets/:id

Important:
Do not add Linear integration yet.
Do not add Sentry integration yet.
Do not add WhatsApp automation yet.
Do not add email sending yet.
Do not build full wallboard yet.
Do not build role-based permissions yet unless existing auth patterns already exist.
This step is only ticket detail viewing, status updates, assignment fields, internal notes, and communication draft/copy blocks.

Backend requirements:

1. Create endpoint:
GET /api/support/tickets/:id

It must:
- return one ticket scoped to active Eride Technologies organisation
- include productName and productCode
- return all support_tickets fields
- return 404 if not found

2. Create endpoint:
PATCH /api/support/tickets/:id

It must allow updating:
- publicStatus
- internalStatus
- priority
- severity
- category
- assignedSupportUserId
- assignedProductOwnerId
- assignedDeveloperId
- assignedQaVerifierId
- pageOrStep
- issueSummary
- whatWereYouTryingToDo
- whatWentWrong
- environment
- applicationReference
- accountReference

Validation:
- publicStatus must use existing public status enum
- internalStatus must use existing internal status enum
- priority must use existing priority enum
- severity must use existing severity enum
- category must use existing category enum
- ticket must belong to Eride Technologies organisation

3. Create support_ticket_internal_notes table if it does not exist:
- id
- supportTicketId
- note
- createdByName nullable
- createdAt

4. Create endpoint:
GET /api/support/tickets/:id/notes

Return notes newest first.

5. Create endpoint:
POST /api/support/tickets/:id/notes

Fields:
- note required
- createdByName optional

Validation:
- note cannot be empty
- ticket must belong to Eride Technologies organisation

6. Create support_ticket_status_history table if it does not exist:
- id
- supportTicketId
- oldPublicStatus nullable
- newPublicStatus nullable
- oldInternalStatus nullable
- newInternalStatus nullable
- changedByName nullable
- changeReason nullable
- createdAt

When PATCH changes publicStatus or internalStatus:
- insert a status history record

7. Create endpoint:
GET /api/support/tickets/:id/status-history

Return status history newest first.
