Fix the post-publish scrolling/cursor/navigation issue caused by the public Lovable UI redesign.

Problem:
After publishing, the public support pages are not functioning properly when moving up/down with the cursor/scroll. The design appears to have introduced an overflow/scroll-lock/layout issue.

Scope:
Fix scrolling and page interaction only.

Affected public routes:
- /help
- /help/report-problem
- /help/track-ticket
- /help/ticket/:ticketReference

Important:
Do not change backend logic.
Do not change API routes.
Do not change database tables.
Do not change ticket creation logic.
Do not change ticket tracking logic.
Do not change reply/upload logic.
Do not change auth, SLA, Linear, Sentry, email, attachments, or audit logic.
Do not remove the new Dogma/Lovable visual design.
Only fix layout, scrolling, cursor, pointer-event, and responsiveness problems.

Investigate and fix:

1. Remove any page-level scroll lock
Check PublicShell, public route wrappers, index.css, and global CSS for:
- overflow-hidden
- h-screen
- fixed inset-0
- min-h-screen combined with nested overflow
- body/html overflow hidden
- position fixed wrappers
- transform/translate wrappers interfering with scroll
- backdrop/gradient layers capturing pointer events

The public page root should allow normal document scrolling:
- html, body, #root should not be scroll-locked
- public pages should use min-h-screen, not h-screen, unless intentional
- decorative glow/gradient layers must use pointer-events-none
- content should sit in normal document flow

2. PublicShell fix
Update PublicShell so that:
- the outer wrapper is min-h-screen
- the hero and content are in normal flow
- background glows are absolute but pointer-events-none
- no wrapper blocks wheel/touch/trackpad scrolling
- mobile Safari/Chrome scrolling works
- desktop mouse wheel and trackpad scrolling works

Suggested structure:
- <main className="min-h-screen overflow-x-hidden">
- decorative backgrounds: absolute inset-0 pointer-events-none
- content wrapper: relative z-10
- avoid h-screen except for intentional full-screen pages

3. Mobile browser fix

- page can scroll vertically
- no horizontal overflow
- sticky/fixed elements do not cover form fields
- inputs/selects/textareas remain tappable
